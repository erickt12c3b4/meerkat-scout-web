## How the port was done (so you can judge the output)

1. **A converter, not hand-typing.** `design_handoff_meerkat_scout_site` is 800KB of inline-styled
   HTML. I wrote a one-off Node converter (parse5 → JSX; shipped under `tools/design-converter/`,
   not part of the build) that maps every inline declaration to a Tailwind class: known hex values
   to the `@theme` tokens, everything else to arbitrary values (`text-[14.5px]`,
   `tracking-[-.035em]`, `rounded-10`, `shadow-hero`). It also: maps file hrefs to routes, turns
   `<img>` into `next/image` with display-size `width/height`, recognises Lucide glyphs by path
   signature, extracts repeated inline SVGs into `components/brand-icons.tsx`, swaps the shared
   header/CTA/footer for the shared components, and adds the baseline responsive classes. The page
   files under `app/` are its output plus hand edits (data-table stacking, hero flow mode, wrap
   fixes). They read as long but literal Tailwind — that is the trade-off chosen for fidelity (see
   judgment calls).
2. **Verification loop.** The original files were served on :3100 (their own `support.js` runtime)
   and the app on :3000; a Playwright script measured every `section`'s height on both and a
   pixelmatch diff located the first differing rows. This is how the line-height and font issues
   below were found; the numbers at the bottom come from the same scripts.
3. **Chrome built once**: `SiteHeader` (+ `MobileNav`), `PreFooterCta`, `SiteFooter`,
   `ContactFooter`. `ChannelPage` + `content/channels/*.tsx` (hero and "distinguishing behavior"
   are bespoke JSX per channel; Connect / Does-and-requires / Depends-on are data).

## Judgment calls (faithful-but-unidiomatic vs clean-but-different)

1. **Fonts are self-hosted copies of the exact files the design loads, not the `geist` npm package
   and not `next/font/google`.** Three Geist builds exist in the wild and their advance widths
   differ by ~0.1–2%: the `geist` package (README's suggestion) was ~2% narrower and changed many
   wraps; `next/font/google` self-hosts a build ~0.1% off Google's CSS-served build, which still
   flipped one line in 11 pages (14–111px drift per page); Google's CSS-API build
   (`css2?family=Geist:wght@400..800&family=Geist+Mono:wght@400..600`) is what 25 of the 26 files
   load, and with it every section on those pages matches to the pixel. So `app/fonts.css` declares
   the 11 woff2 files that stylesheet serves, downloaded once into `public/fonts/` (168KB, latin
   preloaded), with Google's own `unicode-range` splits — no runtime request to Google. The
   homepage file embeds a fourth build (next/font, weights 100–900) whose metrics differ from all
   the others; it is extracted to `public/fonts/home-geist-*.woff2` as `'Geist Home'` and applied
   only to the homepage sections (`font-home`) so that page matches too. Deviation from the
   README's letter in favour of its intent (pixel match); trivially reversible by pointing
   `--font-sans` at any one build.
2. **`html { line-height: normal }`.** The 25 `.dc.html` files have no CSS reset, so every line
   without an explicit `line-height` used the browser default; Tailwind's preflight sets 1.5, which
   made the footer 22px taller and drifted every page by 2–8px per section. Setting `normal`
   globally restored exact heights. The homepage was the one file built on preflight (1.5), so its
   sections carry `leading-normal` explicitly. Unidiomatic for Tailwind, but it is what the design
   is.
3. **Arbitrary values everywhere, tokens where the README lists them.** `p-[22px] pb-[20px]`,
   `text-[15.5px]`, `grid-cols-[minmax(0,1fr)_600px]` rather than the nearest scale step. The user
   asked for this explicitly ("never Tailwind's default scale"). Colors/fonts/radii/shadows are
   tokens (`bg-paper`, `text-rust`, `rounded-12`, `shadow-hero`); one token was renamed mid-way
   (`muted` → `dim`) because it collided with shadcn's `--color-muted`.
4. **Lucide only where the paths match the current Lucide set.** Only 24 of 125 distinct stroke
   glyphs in the files are literal current-Lucide paths (42 match a 2024 Lucide); the rest are the
   designer's own variants (a shorter arrow head, a rounder shield, custom circle-checks…). Those
   are kept as inline SVG (shared components when reused: `ArrowRightGlyph`, `ShieldGlyph`,
   `CircleCheckGlyph`…) so the shapes are exactly the files' shapes. Pinning `lucide-react` to an
   old version would have caught 18 more glyphs and fought shadcn's icon imports; not worth it.
5. **`box-content` where the files relied on it.** No reset means `width + padding` elements were
   content-box in the files; the converter adds `box-content` only where padding/border affects the
   sized axis. Ugly, correct.
6. **Above 1440 the content column stays centered** (`--gutter` grows) instead of stretching as the
   files would at 1920. Backgrounds still run full-bleed. Absolutely positioned decorations inside
   gutter sections are re-anchored to the content column (`left-[calc(var(--gutter)-70px+80px)]`).
7. **Shared chrome on the homepage.** The approved homepage file still had the old
   `scout-cta.png` CTA, a header whose nav pointed at in-page anchors and a footer at line-height
   1.5. DEV-HANDOFF says to port the shared pre-footer there "when it is next opened", and README
   says the header/footer are identical everywhere, so the homepage now uses the shared components
   (Book a demo → `/demo`, Platform → `/#platform`, Channels → `/channels`, Resources → `/help`,
   Pricing → `/pricing`). The homepage's in-page `#channels` / `#resources` / `#pricing` anchors still
   exist; only the nav no longer targets them. Its own "Start your 14-day free trial" keeps
   `#start-free-trial` as the file had.
8. **Contact posts nothing to the API.** The design's Contact logic is `mailto:` only and
   DEV-HANDOFF says replace it "when a form endpoint exists". I left it exactly so (server
   verification of the checkbox token would require a round trip that the design does not have),
   and routed only the demo lead through `/api/lead`. Easy to change: `ContactForm.submit`.
9. **`/api/lead` when `LEAD_ENDPOINT` is empty returns `delivered:false`** and the browser falls
   back to the mailto draft — this keeps server-side reCAPTCHA verification on every demo
   submission while preserving the design's "blank endpoint = mailto" rule. Untokened leads
   (reCAPTCHA blocked) are accepted and flagged `verified:false` per DEV-HANDOFF's "leads over
   friction"; flip `ACCEPT_UNTOKENED` to quarantine.
10. **shadcn components are used, then overridden at the call site** (`cn` is tailwind-merge
    compatible): `Input`/`Textarea`/`Label`/`Button`/`ToggleGroup`/`Accordion`/`Sheet`. Their default
    8px-radius/32px-height styles are replaced by the design's 46px inputs, 54px buttons, 66px tiles.
    I did not add cva size variants inside `components/ui/*` (kept those files as generated) — a
    reviewer who prefers variants over call-site overrides should move the class strings from
    `components/forms/*.tsx` into `button.tsx`/`input.tsx`.
11. **Pricing FAQ**: the file used native `<details>`; the user asked for shadcn Accordion. Built on
    shadcn's `Accordion`/`AccordionItem`/`AccordionContent` with a custom trigger (base-ui
    `Accordion.Trigger`) so the 20px rotating chevron matches the file instead of shadcn's 16px
    swap icons. `firstFaqOpen` / `oneOpenAtATime` props kept.
12. **Pricing cards stack at 900px, not 768**, because the Pricing file is the only design file
    with its own breakpoints and 900 is its rule.
